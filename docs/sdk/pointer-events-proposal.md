# Queued pointer input v1

Approved by the project owner on 31 October 2026 under roadmap §31.
Implemented as ReadPointerEvent=90. This is additive to the native ABI;
existing snapshot calls and gui-v1 wire bytes retain their contracts.

## Problem and evidence

The compositor currently reads GetMouseState=60 once per desktop iteration and
derives button edges from two snapshots. A complete down/up between snapshots
is invisible. The kernel already records MouseEvent values in a bounded ring,
but there is no userspace operation to consume them.

On ed32e1f under QEMU 10.0.13 TCG, the native SDK buttons scenario failed twice
at the final pointer activation with its original 200 ms intervals. The same
required/forbidden markers passed with 1000 ms intervals. Themes and SVG UI
also passed only with longer pauses. This is evidence of input timing sensitivity;
the snapshot implementation explains how edges can be lost. Increasing delays
is diagnostic, not a production fix.

## Accepted additive contract

ReadPointerEvent=90 is declared in abi/syscalls.abi; Rust and C syscall numbers
are generated by the existing generator. The number was checked against the
fetched main branch before implementation. `abi/pointer-input` owns the Rust
record codec shared by the kernel and libdunit.

Arguments are an INPUT_MASTER handle, an output address, and an output byte
length. V1 requests use exactly 32 bytes; the separately approved
[modifier snapshot extension](pointer-modifier-snapshot-proposal.md) adds an
explicit 40-byte request while preserving these v1 bytes. The handle must be
owned by the caller and carry the existing INPUT_MASTER right. No new rights
bits or ambient input privilege are introduced.

The little-endian record has the following fields:

| Offset | Type | Meaning |
| --- | --- | --- |
| 0 | u32 | absolute x in the published display bounds |
| 4 | u32 | absolute y in the published display bounds |
| 8 | u32 | button mask: left/right/middle in bits 0/1/2 |
| 12 | i32 | wheel delta belonging to this event |
| 16 | u64 | event sequence, in production order |
| 24 | u32 | flags; bit 0 means events were lost before this record |
| 28 | u32 | reserved, zero |

Success returns 0 and consumes one event. An empty queue returns EAGAIN;
wrong length returns EINVAL, invalid user output returns EFAULT, and an
unauthorised handle returns EACCES. Failed copies and invalid arguments do not
consume input. Capability acquisition/release must reset the consumer baseline
and prevent a new owner receiving a previous session's queued input.

The queue stays bounded and IRQ-safe. Consecutive pure motion events may be
coalesced only with identical button state and without discarding wheel deltas.
Button changes preserve order. Saturation must be explicit through LOST_BEFORE;
the consumer cancels capture/press state and resynchronises instead of fabricating
a click. The first record on ownership acquisition is also a LOST_BEFORE baseline:
a button already held when the seat is acquired must not synthesize a new press.
Sequence gaps can also mean motion coalescing; only LOST_BEFORE requests resync. Kernel code stores device facts; userspace chooses cancellation policy.

GetMouseState=60 and its wheel-accumulator semantics remain unchanged. No gui-v1
wire bytes change. A safe libdunit wrapper exposes Result<Option<PointerEvent>>.
The compositor consumes one queued record per render iteration and routes
transitions in order, using that record's coordinates. Remaining records stay
queued; pure motion coalesces in the kernel. This bounded budget preserves
render/IPC progress. EAGAIN keeps the last consumed state with zero wheel delta,
rather than reading a newer snapshot ahead of queued events. Events queued
before a live modeset are clamped to the new display bounds. Existing GUI control messages remain the client transport.

## Alternatives

Keep snapshots and proceed to the next M7.6 widget: no ABI change, but the known
short-click failure remains. Raising polling frequency or slowing test input
does not guarantee preservation of transitions between reads. Reinterpreting
GetMouseState as a queue read silently changes its existing contract and is not
recommended.

## Verification contract

- ABI generator consistency; existing syscall numbers and snapshot behaviour.
- Queue host tests: down/up without intervening reads, ordering/coordinates,
  coalescing, saturation/resynchronisation and bounded storage.
- Native negative tests: INPUT_MASTER isolation, wrong length, invalid output,
  EAGAIN, and no event loss on failed copies.
- A QEMU regression injecting a complete click while the compositor cannot
  sample it, then asserting exactly one activation and correct cancellation.
- Original SDK buttons, checks, input, scroll and autoscroll scenarios with their
  original timing and marker expectations; theme/SVG UI and GUI smoke.
- Headless GUI protocol tests and boot regression. Repeat the original
  high-resolution switching scenario before claiming its failure fixed.

## Verified on 31 October 2026

QEMU 10.0.13 / TCG: the native pointer queue test preserved a 40 ms down/up pair
while its reader slept for 1500 ms. It also verified capability isolation,
EFAULT/EINVAL without consuming the baseline, EAGAIN and ownership handover.

All 13 native GUI SDK fixtures passed with their original timing and markers:
buttons, checks, input, multiline, scroll, scroll_xy, autoscroll, resize,
component, theme, effects, backdrop and motion. The original Settings, themes,
SVG and five-resolution sequence passed; the 3072x1920 to 2880x1800 transition
that previously stalled is now confirmed. Boot, snapshot pointer geometry,
wait-set, SDK API, DWM engine, production DWM boot and headless GUI protocol
regressions passed. GUI smoke needs a longer observation budget under TCG to
capture its final recycle self-test; the marker expectations remain unchanged.

Host verification covers the shared wire codec, queue ordering/coalescing/
overflow, hardware-independent geometry and failed-copy preservation, DWM
regressions and the native runtime/component tests. The host geometry adapter
uses a mutex instead of privileged CLI/STI; actual interrupt/capability paths
are exercised on the kernel in QEMU. This closes queued pointer delivery, not
the remaining M7 widget, clipboard or keyboard-up protocol work.
